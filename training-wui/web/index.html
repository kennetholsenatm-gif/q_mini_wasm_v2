1 · Dataset mix

Pick Hugging Face datasets to combine (no fixed cap). Step 3 · Data source reads this mix when data.path is qminiwasm/hf-multi. Apply mix & save writes the working TOML and jumps to step 2 — you can also use Next and save from step 5. Skip this step if you use a single dataset preset in step 3.

The engine loads at most this many rows once per training run (divided across selected datasets), then trains for multiple epochs on that in-memory slice — it is not re-downloading the full Hub split every epoch. Use a lower number to put huge datasets on a diet (less RAM/time).

Add custom Hub dataset
Custom entries (click × to remove)

2 · Model & device

Model name, accelerator, and quantum settings written to the working TOML. Where training runs (local, RunPod, serverless) is set in the header Execution target, not here.

Checkpoints and agent files go under artifacts/models/<slug>/ (final, best, latest .pt, plus serve.toml and agent_bundle.json).

3 · Data source

Mesh vs Hugging Face, presets, primary path, and optional multi-dataset extras. When step 1 has a mix, primary path and extras follow that mix.

Choose a preset to auto-fill dataset id and config. If step 1 has a dataset mix, prefer Multi-dataset or leave primary empty / qminiwasm/hf-multi.
Additional HF datasets (optional; any number combined with the primary path)

Mix is defined in 1 · Dataset mix — the checkboxes below are hidden so you do not configure two different lists. Clear step 1 or use a single-dataset primary to use these extras again.

When not using step 1 mix: check extras to combine with the primary id. With primary qminiwasm/hf-multi, extras come from step 1 if you selected catalogs there, otherwise from these boxes. Row cap from step 1 applies to the merged list; hybrid mesh blend runs after merge.
Required for hf_tabular and hybrid mode. Reserved qminiwasm/hf-multi skips a primary Hub load; select at least one extra below.
Advanced data options
Subset name for multi-config datasets (e.g. python on CodeSearchNet). Leave blank for default — shows as (none) in facts; many datasets (e.g. NuminaMath-CoT) use a single config.
Hard cap on how many row vectors load from Hub once per run (split across merged datasets / mix). Syncs from step 1 row budget when using a mix. Leave blank for automatic sizing. Env HF_NUM_SAMPLES or TOML [huggingface] num_samples also apply.

4 · Training & every TOML field

Native LibTorch TPEM (default): d_model and num_ternary_blocks size the ternary STE stack; io_d_model is encoder / mesh–HF row width. Saved under [model] — gRPC StartTraining uses these for cold start when no checkpoint/tpem load path is set (stem/head when io_d_model ≠ d_model).

Optional Python loop: the same TOML drives EngineConfig if you run python -m qminiwasm.engine instead of native.

Epochs / batch / LR and data paths are set in steps 1–3 and the quick grid above — the schema list below skips those keys so you do not edit them twice. Use Save working config (wizard or schema) to write the same file.

Row vectors — where to set counts vs width: Width of each input row (how many numbers per mesh/HF vector, often 4096) → io_d_model below. Internal / hidden width after stem → d_model below. How many row vectors per training step → Batch size below ([training].batch_size). How many rows total loaded from Hub for the run → 1 · Dataset mix → Max Hub rows to load, or 3 · Data → Advanced data options → HF max rows (num_samples).

Training steps & vector geometry

Model Facts

Deploy to serve

After agent_bundle.json and serve.toml exist for this model, start a local HTTP API (uvicorn on 127.0.0.1) and generate docker-compose.serve.yaml in the model folder.

Launch training

Default path is the native C++ engine (LibTorch over gRPC at configs/wui.toml grpc_addr). Start qminiwasm_training_engine_server first (e.g. scripts/start-training-stack.ps1). For the full Python PyTorch loop instead, set training_runtime_mode = "python" in configs/wui.toml or use auto to fall back to Python if gRPC is down.

Only this button starts the engine. Pick the TOML (usually wui_working.toml). Quantum settings come from step 2; execution target from the header — you confirm both in the launch dialog. RunPod Serverless: if no endpoint id is set in header Target options, launch can create a short-lived template and endpoint.
