1 · Dataset mix

Pick Hugging Face datasets to combine (max 9). Step 3 · Data source reads this mix when data.path is qminiwasm/hf-multi. Apply mix & save writes the working TOML and jumps to step 2 — you can also use Next and save from step 5. Skip this step if you use a single dataset preset in step 3.

The engine loads at most this many rows once per training run (divided across selected datasets), then trains for multiple epochs on that in-memory slice — it is not re-downloading the full Hub split every epoch. Use a lower number to put huge datasets on a diet (less RAM/time).

2 · Model & where it runs

Name outputs, choose GPU/RunPod, and quantum behavior. Matches the launch card in step 5 after you save.

Checkpoints and agent files go under artifacts/models/<slug>/ (final, best, latest .pt, plus serve.toml and agent_bundle.json).

Training uses the same wizard flow. Launch training (step 5) creates a short-lived RunPod template and endpoint when needed, using the worker image from your selected training TOML ([runpod_serverless] worker_image) or the built-in default. Serverless template create omits disk/volume fields (RunPod rejects them). Your worker must accept qmw_schema_version, qmw_action: train, and config_rel.

Choose a preset to auto-fill dataset id and config. If step 1 has a dataset mix, prefer Multi-dataset or leave primary empty / qminiwasm/hf-multi.
Additional HF datasets (optional; max 8 with a normal primary, or 9 in extras-only mode)

When not using step 1 mix: check extras to combine with the primary id. With primary qminiwasm/hf-multi, extras come from step 1 if you selected catalogs there, otherwise from these boxes. Row cap from step 1 applies to the merged list; hybrid mesh blend runs after merge.

Advanced data options
Subset name for multi-config datasets (e.g. python on CodeSearchNet). Leave blank for default — shows as (none) in facts; many datasets (e.g. NuminaMath-CoT) use a single config.
Hard cap on Hub rows loaded once per run (split across merged datasets / mix). Syncs from step 1 row budget when using a mix. Leave blank for automatic sizing. Env HF_NUM_SAMPLES or TOML [huggingface] num_samples also apply.

Model Facts

Launch training

Only this button starts the engine. Pick the TOML (usually wui_working.toml). Run target and quantum settings come from step 2 — no second copy here. RunPod Serverless: if no endpoint id is set (step 2 Advanced), this button creates a short-lived template and endpoint, then starts training.

Preflight UNKNOWN

Uses the config file from the launch card. After saving the wizard, select wui_working.toml and refresh. Preflight accelerator can follow ?accelerator= from step 2 when you refresh after save.

IBM pending jobs is that backend’s queue length (jobs waiting to run there). 0 is normal when nothing is queued—your training may use the simulator first, or you haven’t submitted IBM Runtime jobs yet.
